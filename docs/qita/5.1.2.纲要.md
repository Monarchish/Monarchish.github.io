# 纲要

一、核心哲学

本手册是一套面向未来自己的、可无脑执行的操作系统。其目标不是"记录知识"，而是将经验编译为精确的、不可再分的指令序列。所有规则皆为此服务：消除歧义，降低认知负荷，确保无论时隔多久、状态多差，都能按步骤完成操作。

二、架构体系

1. 组织层级

采用"司-局"二级架构，命名均为二字词，结构为"动词+动词"或"动词+名词"。

司：业务大模块。如"准入端"、"采购端"、"销售端"、"销售端"、"勤杂组"。

局：司下的子模块。如"准入"、"MDG"、"订货"、"销售合同"。

层级分隔符：·（空格+中点+空格）。示例：准入端 · 准入 · 邮件审批

2. 命名原则

职能明确：名称直接反映该模块的核心工作。

现代专业：风格参考现代职能机构（如香港警队部门命名），简洁有力，不刻意古典。

无重复字：所有"司"名中，核心动词互不重复，确保名称独立、不混淆。

三、格式与排版规范

1. 模块分隔

用等号构成的线条分隔主模块。

2. 标题层级

模块标题直接写在分隔线之间，层级清晰。

四、指令代码规范

1. 操作指令词

所有操作指令使用英文，常用指令词如下：

Open：打开某个软件、网站、文件路径

Write：在字段中输入由变量决定的确切值

Left Click：鼠标左键单击

Right Click：鼠标右键单击

Double Click：鼠标左键双击

Ctrl + C：复制

Ctrl + V：粘贴

Ctrl + D：向下填充/复制上一格

Ctrl + F：查找

Ctrl + S：保存

Ctrl + Alt + A：截图

Filter：筛选

Enter：回车确认

Esc：退出当前状态

2. 操作对象

操作对象（如软件名、字段名、按钮名）使用双引号包裹。

3. 操作值与变量

变量：需要根据实际情况填入的内容，用方括号包裹。如：【客户名称】

固定选项：用 Or 连接。如：（央企 Or 国企）

保留字：系统内约定俗成的短代码，直接书写。如：（15%定金，带款提货）

4. 层级连接

当操作对象有层级关系时，用 -（空格+短横+空格）连接。

5. 分隔与停顿

软件窗口切换：用 ---（三个短横）分隔，表示从一个软件切换到另一个。

等待：暂未设置专门指令词，但在逻辑上隐含，如发送邮件后需要等待审批。

五、逻辑控制与注释

1. 分支与条件判断

使用 ⚠ 符号开头，表示一个重要的检查点或决策点。

检查点：注意看"R - U"是否为"TRUE"。如果不是则需要检查原因。

决策点：如果仓库回复在库，告知客户。如果仓库回复不在库，继续下一步。

2. 注意事项

非操作指令的提示、说明、背景知识，直接书写，不加任何特殊符号。
